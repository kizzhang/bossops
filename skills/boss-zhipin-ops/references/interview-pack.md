# 面试简历评估包（SWOT 包）：怎么分析、怎么打包

给**已确定约面**的候选人，在面试前做一份「评估页 + 原始简历」的 PDF，给面试官面试时看。
评估页回答三件事：这个人值不值得面、简历里哪些话要当面核对、该问什么。

## 一、什么时候做、什么时候不做

- **只给确定约面的人做**：正式「约面试」卡片已被接受，或对方已明确确认了时间。还在挑时段、只是「建议推进」的，不做。
- 用户问「简历 swot 有没做的吗」，就对照日历里已确认的面试，找没有 PDF 的人补做。
- **评估包不要往外发**（包括聊天群、网盘链接）。它含候选人的简历和评价，只放在用户本机的约定目录里，由用户自己取。

## 二、输入：先把原始简历拿到手

| 情况 | 做法 | 评估页里怎么写 |
|---|---|---|
| BOSS 有附件简历 | 附件 PDF 是准的，学校/年限/GPA 以它为准，数据里写 `src_pdf` | 落款写「BOSS 附件简历」 |
| 没有附件 | 用在线简历截图（只读打开，截几屏拼成图），数据里写 `src_imgs` | 「教育」「新口径核对」里写明「**仅在线简历，未核实**」；落款自动写「在线简历截图（未核实）」 |
| 附件只有 BOSS 预览图（没下载） | 当截图用，同样标「未核实」 | 同上 |

- **BOSS 在线简历里的学校是本人填的**，可能和附件不一致。有附件以附件为准，差异写进「要核实的点」。
- 拿原始简历的过程仍是 BOSS 作业，受本 skill 其它章节约束：只读、随机延时、不点链接、需要简历时先问用户怎么要。

## 三、评估页的版式（固定，不要改结构）

**第 1 页，从上到下：**
1. 抬头：左边大字姓名，下一行「年龄 岁 · 投递岗位；建议按 X 岗面」；右边大字「总分 分」，下面「置信度 NN%」。
2. 信息表（左列表头）：面试时间（`北京 MM-DD 周X HH:MM ｜ 你本地 MM-DD 周X HH:MM ｜ 平台`）、教育、新口径核对、一句话结论、置信度说明。
3. 分项打分（满分 100），固定 5 项，最后一行合计。
4. 「要核实的点」：橙色框，列简历里需要当面核对的说法。
5. SWOT 四格表：S 优势 / W 劣势 / O 机会（对我们）/ T 风险，每格 2–4 条，写具体经历和数字，不写空话。

**第 2 页：面试问题**——6–8 题，每题下面一行灰字「听什么」；最后一题固定问去向。页底小字落款由脚本生成。
后面接原始简历。**脚本会自动排版以上全部**，你只需要写数据。

## 四、数据文件怎么写

复制 `scripts/cands_example.py`，改名 `cands_<日期>.py`，一个文件放一批人。字段：

| 字段 | 内容 |
|---|---|
| `name` `age` | 姓名、年龄（数字） |
| `job` | BOSS 投递岗位 + 建议面的岗位，如 `"AI应用开发工程师；建议按科研岗面"` |
| `bj` `la` | 北京时间和用户本地时间，**两边都要写**。夏令时切换前后时差不同，别信沙箱时区库，按 BOSS 上显示的北京时间手算，并和日历对一遍 |
| `platform` | 面试平台和会议号 |
| `edu` | 本科 → 硕士 → 博士，每段：学校、专业、年份、层次（985/211/QS100/普通）；能写 GPA/排名就写 |
| `rule` | 筛选口径核对：开头用 ✅ / ⚠ / ❌，逐项写年龄、**本科**层次、期望薪资、非全日制/独立学院/继续教育/分校区 |
| `scores` | 5 个整数，顺序同下表；合计即总分 |
| `conf` `conf_why` | 置信度 0–100，说明能核实什么、哪里前后矛盾、扣分点 |
| `verdict` | 一句话结论：能不能用、最大风险是什么 |
| `S` `W` `O` `T` `flags` | 各是字符串列表；`flags` 是「要核实的点」 |
| `Q` | `[(问题, 听什么), ...]`，6–8 个，最后一个是去向题 |
| `src_pdf` / `src_imgs` | 原始简历路径，见第二节 |

文件顶部写 `DATE = "2026-11-06"`（落款日期）。

筛选口径（年龄上限、薪资线、985/211 怎么认）由你的团队定，写在 `rule` 里逐项核对即可。示例口径：年龄不超过 32；本科才算 985/211；分校区、独立学院、继续教育、非全日制不算。

## 五、怎么打分（5 项，固定）

| 项 | 满分 | 怎么给 |
|---|---|---|
| 岗位匹配 | 25 | 经历和在招岗位的对口程度。已有实际做成的东西 20+；方向沾边 15–19；偏离 <15 |
| 技术/科研深度 | 30 | 能讲出机制、能被追问的深度。有一作论文、可核实的开源贡献、完整的指标和做法 24+；有真实项目但细节少 17–23；只有堆栈名词 <15 |
| 学习与思维信号 | 20 | 复盘、归因、取舍、定位根因的痕迹。全是 agent/RAG 名词堆砌就降分；「用 AI 工具辅助」这类话术已经泛滥，只看能否说清用它做成了什么 |
| 学历口径 | 15 | **只看本科**。985 理工 / 海外 QS100 本科：13–15；211 理工：11–13；普通本科：3–9；独立学院、非全日制、继续教育、分校区：≤5。硕博不救本科 |
| 风险与稳定性 | 10 | 去向（在职/转正/他处 offer）、期望城市不符、时间线重叠或矛盾、简历夸大、到岗时间。风险越多扣越多 |

分数分三段用于对照：80 以上是强，可以直接推进；60–79 是可面；60 以下要有明确的补偿理由才面。同一批人用同一把尺，**不要这个人宽、那个人严**。

评分报告和评估包分数不一致时，**以评估包为准**，并回头改报告和台账（报告末尾追加更正，不要改动原分）。

## 六、写作规矩

- **S/W/O/T 要具体**：写经历、数字、年份、项目名。「基础扎实」「学习能力强」这种空话不要。
- **扣分点和夸大要写出来**：比如「3 篇顶会只有 1 篇一作」「『顶刊级成果』其实是拟投稿」「时间线重叠」。这是评估包最有价值的部分。
- **面试问题**：
  - 每题必须指向简历里某一段具体经历或某个数字，不问通用八股；
  - 「听什么」写成：真做过的人会怎么答，背简历的人会在哪里露馅；
  - 能当场心算的数字（吞吐、成本、占比）就让他算，答得出量级的是真跑过；
  - **最后一题固定问去向**：在职/转正情况、期望薪资和城市、到岗时间。
- 超出筛选口径的项（年龄、薪资线）要在评估页里标出来；是否「特别优秀」由用户定，只标出来不替用户决定。

## 七、生成与检查

```bash
python scripts/build_pack.py cands_<日期>.py [姓名 ...]
```

- 依赖 `pymupdf`（`pip install pymupdf`）。脚本里字体默认读 `C:\Windows\Fonts\simhei.ttf`，别的系统用环境变量 `PACK_FONTS` 指到含 `simhei.ttf`（或你改过 CSS 里的字体名）的目录。
- 输出到 `PACK_OUT`（默认 `./packs`），文件名 `<姓名>_<总分>分.pdf`，终端打印：姓名、总分、置信度、评估页数、总页数、路径。**评估页 1–2 页为正常**；超过说明内容太长，压缩 S/W/O/T 或问题。
- 重新生成会得到新文件名（分数变了文件名也变），**旧分数的 PDF 要手动删掉**，别留两份。
- 生成后至少打开一份看版式：中文是否乱码、橙框是否在、页底落款是否在、原始简历是否接在后面。

## 八、做完后同步

1. 日历里该人的面试事件已存在，评估包的面试时间要和它一致。
2. 台账里记总分和评估包路径。
3. 评分报告（如有）按评估包分数更正。
4. 交接文件记一笔：做了谁、分数、数据文件名、未核实项，防止下一个会话重做。
5. 告诉用户：做了谁、分数、最大风险、哪些靠截图未核实。

## 九、常见的坑

- **评分结构中途换了**：开做之前先和用户确认格式。打分项一旦换过，旧批次的分数就和新批次没法比，要么全按新的重算，要么旧的作废。
- **学校以附件为准**：在线简历和附件不一致时，评估页和台账都改，并写进「要核实的点」。
- **海外院校别凭印象**：按 QS100 口径视同 985 的，在 `rule` 里写明依据；不要凭印象说「海外不算」。
- **没有附件的人也要做**：明确标「未核实」，不要因为只有在线简历就跳过。
